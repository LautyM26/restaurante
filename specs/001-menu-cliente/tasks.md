## Reglas para todas las tareas
1. **TDD estricto:** primero los tests en rojo (referencian código que todavía no existe), después el mínimo código para pasarlos, triangular con un segundo caso y refactorizar con la suite en verde.
2. **Una tarea por vez y en orden.** Cada tarea solo usa lo que crearon las anteriores. "Crea" = archivo nuevo; "Modifica" = archivo de una tarea anterior.
3. **Hecha** solo con `npm test` en verde y `npm run build` sin errores. (`opencode/agents/implementer.md` dice `node --test`: en este proyecto es `npm test`; ver plan §1.2.)
4. **Verificación visual móvil (constitución §3)** en toda tarea con interfaz: MCP de Chrome DevTools a 375 × 812 y 320 × 568 como mínimo, sin scroll horizontal; se adjunta la evidencia (capturas o descripción) al reporte.
5. **Accesibilidad:** cada test de pantalla u hoja incluye `expectNoA11yViolations(container)` (plan §13).
6. **Skills obligatorias:** leer las skills indicadas en cada tarea (en `skills/<nombre>/SKILL.md`) y cerrar el reporte con **"🛠️ Skills Aplicadas"** (qué skill se usó para qué decisión, o por qué no aplicaba).
7. Si la tarea o el plan son incorrectos o imposibles, PARAR y avisar (constitución §1). No improvisar.
